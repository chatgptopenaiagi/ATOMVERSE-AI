# Roadmap

## Mission 002A — 0.2.0-alpha.2

Standalone Windows EXE, installed Python wheel and native Android ARM64 distribution share one scientific core. Preserve 0.2.0-alpha.1 assets and classify Android device coverage separately from compilation. Current platform results are recorded in Mission 002A evidence.

Next: physical ARM64 phone/tablet coverage across supported Android versions; accessible mobile scientific tables; Android CSV export and optional authorized local AI endpoint; additional desktop OS adapters only after actual runtime testing. No unsupported sensor or model capability is promised by a package tag.

## Gate 1 — public genesis

**Completed:** public documentation commit and remote readback recorded in EVIDENCE/STAGE-1-VERIFICATION.json.

Preserve the original idea and mission; publish documentation only; verify account, public visibility, commit, README, vision and roadmap remotely; record sanitized evidence. No application implementation before this gate.

## Gate 2 — evidence-based discovery

**Completed for the alpha:** fresh ARX/runtime probes, official engine review and a dependency/reuse matrix. Exact historical Qwen model paths are unavailable; discovery is not an exhaustive whole-disk inventory.

Measure actual workstation capabilities. Inspect ARX, COG, DRAGONHYDRA and Qwen without modifying them. Review owner repositories and official engine documentation. Produce a dependency/reuse matrix and architecture decision with alternatives, packaging, resource costs and offline behavior.

## Gate 3 — first working vertical slice

**Verified:** actual Windows executable, 46 tests, real ARX intake, deterministic visualization, SQLite persistence, CPU/CUDA benchmarks, errors, replay, export and shutdown. See ATOMVERSE-FINAL-REPORT.md for precise scope.

Implement validated events, deterministic visual scores, SQLite persistence, explicit ARX intake, interactive universe, precise tables, bounded CPU and optional GPU benchmarks, replay, atomic JSON exports, and clear errors. Provide visibly separated synthetic demonstration data. Package a Windows executable and test the actual binary.

## Mission 002 — continuous observation, 0.2.0-alpha.1

Implemented: isolated live hardware/process observation, explicit scientific categories, additive memory migration, bounded retention, historical comparisons, optional engine-export adapters and evidence-linked local AI. Verification reports cover source tests, actual packaged execution and measured observer/rendering overhead. CPU temperature, per-process GPU utilization, reliable WDDM process VRAM and disk response-time measurement remain unavailable.

## Next — broader evidence and usability

Priorities: longer-duration soak tests, retention trend summaries, time-range window selection beyond the current bounded replay view, analytical comparisons under controlled workload conditions, additional reliable sensors, richer process layout and local-model latency reduction. Optional COG/DRAGONHYDRA production exports still need operator-selected real-world validation; fixtures do not establish live connectivity.

## Gate 4 — breadth and intelligence

Add richer telemetry, model-serving integration, code/dependency maps, benchmark comparisons, evidence-grounded explanations and retained history. Support the ten primary views: Universe, Benchmark Arena, Data Tables, AI Intelligence, Knowledge Memory, Hardware Map, Software Map, Source Code Galaxy, Guardian, Settings.

## Gate 5 — experiments

Investigate instanced 3D rendering, richer simulations, comparable regression detection, analytical storage, and modular integrations. These remain experiments until verified.

Both 0.1.0-alpha.1 and 0.2.0-alpha.1 are experimental milestones. Publish only after documented acceptance and actual binary verification. Future capabilities remain proposals until verified.
